# 地域で暮らす語学生活ゲーム：設計方針 v0.1

2026-10-18（日本時間）。本人が具体化した構想と、作成者の追加案を分けた設計記録。完成した制作SPECではなく、国・言語・町・端末・教材・数値の未決定事項を残す。コードの実装開始を意味しない。

## 1. 目指す体験と独立作品の方針

一作品の舞台となる国と学ぶ言語を固定し、その地域の町で暮らす。本人は、近年のポケモンのように主人公を操作して町を歩き、地域の景色・町並み・人を見ながら、買い物・会話・簡単な仕事をしたいと説明した。3Dの街と主人公を見ながら歩く表現を有力候補とするが、カメラ・等身・描画方式・端末は未確定。

複数の国・言語を一作品へ詰め込む必要はない。言語ごとに別作品として、町・生活・教材・遊びを選べる。語学ゲーム全体を単一方式へ統合しない。

町は一つでも成立する。景色や生活の特色の違う複数の町を収録するなら、町ごとの住まいを選択し、後から引っ越せる。町数を増やすことを制作開始の必須条件にしない。言語や地域の選定はまだしていない。

## 2. 今回、本人が具体的に述べた条件

| 項目 | 決まった方向 |

| 町 | プレイヤーは町並み・道・建物配置を作り替えない |
| 住まい | 既存の集合住宅等の一室を借りる賃貸。家を一から建てない |
| 所有・契約 | 同時に住める家は一つ。複数町の家を同時保有しない |
| 住居選び | 用意された間取りから選ぶ方向。壁を建てて自由設計する指定ではない |
| 引っ越し | 複数町がある場合等に転居できる |

| 建物の外装 | プレイヤーによる変更は不要 |

| 天井 | 編集は必須ではない。将来追加してもよい |

上の表は本人の発言の整理。以下の運用・数値・実装方法は作成者の提案として区別する。

## 3. 住まい・引っ越し・家具の設計案

### 3.1 一軒だけの住まい

進行データに「現在の住居」を一つ持つ。町と部屋の組で住まいを表す。別の家を別荘として同時に保有する機能は今回の条件に含めない。他の町への短い訪問と、居住先の変更は別の行動として扱う候補。

候補の部屋には、間取り、家賃、窓からの景色、店や仕事場までの距離等の違いを設けられる。これはゲームの選択肢案であり、実際の国の賃貸制度・価格を確認したという意味ではない。契約の法制度を再現する場合は別途公式調査が必要。

引っ越しの候補手順：候補を内見→条件を確認→転居を確定→荷物を保管箱へ→新居で配置。新居に入りきらない家具は保管して失わせない。費用不足やセーブ失敗で家を二重契約・無住居にしないよう、転居は一つの確定処理として扱う。家具付き物件・持ち込み家具の区分、費用・契約更新・家賃の周期は未定。

### 3.2 床と壁のマス

床の家具には占有する形を持たせる。例：1×1、1×2、2×2。これらは説明用であり、完成教材・全家具リストではない。回転すると占有範囲が変わる。範囲外、他家具、ドア、必要な通路等との重なりを検査する案。

床の占有、歩ける範囲、家具の使用に必要な場所は別に考える。家具が置けるだけで、ベッド・椅子・台所が使えると扱わない。背の高い家具・低い家具・机上の小物・壁の飾りを一律の占有判定で潰さない。こうした細部の対応範囲は正式SPECで絞る。

壁の飾りは壁面ごとのマスへ置く案。窓・ドア・壁の飾りの重なりを扱う。壁際の机とその上のポスターが両立するか等は、物の高さと設置範囲から決める候補。

**未確定の発言**：本人の「机を壁際に置いたらそこのマスの壁判定…消される」は、壁面の設置枠の競合、視認性のための壁の非表示、その他のいずれを指すか確定できない。勝手に「机の後ろの飾りは消す」等へ仕様化しない。壁を透かす描画と、壁飾りの設置可否は別項目として扱い、画面例等で確認する。

床・壁のグリッドの実寸、回転単位、窓・カーテン、机上配置、編集モード、取り消し、保管箱は次の仕様化事項。天井編集は初期必須条件にしない。

## 4. 仕事・お金・料理がつながる日常

仕事で稼ぐ→食料・服・家具・趣味の品を買う→家や日常が変わる、という循環を候補とする。住民のお願い、カフェ、配達を全て同じ単語入力の出題にしない。

| 活動 | 主な遊びの候補 | 言語が必要になる理由 |
|---|---|---|
| カフェ | 注文・数量・持ち帰り等を把握し品を出す | 客の希望を聞き分けて行動を変える |
| 配達 | 受注選択・複数受注・期限・道・入口・集荷 | 品・数・店・住所・位置を理解する |
| 住民のお願い | 買い物代行、届け物、探し物等 | 相手の目的と対象を確かめる |
| 買い物 | 商品・価格・数量・店の特徴を見る | 名前だけでなく必要な物を選ぶ |
| 自宅料理 | 食材の購入、保存、手順、完成品を使う | 食材・数量・動作を実際の操作につなぐ |
| 食事・外食 | 家で食べる、店や催しへ行く | メニューや好みの短いやり取り |

料理は店の仕事と自宅での活動を区別できる。全ての料理を反射速度のミニゲームにする必要はない。調理設備、道具、食材、レシピ、食べる／売る／贈る等の用途は今後選ぶ。現地料理は地域の出典と、現実の作り方／ゲームの省略を分ける。

生活費と装飾品の値段、仕事一回の報酬・時間、家賃の頻度は一緒に調整する。収入が不足すると全ての遊びが仕事だけになるため、自由な日常が残るかプレイで確認する。空腹・衛生・借金・退去などの細かいペナルティを、生活ゲームの名称だけから必須にしない。

## 5. ゲーム内時間と季節（方式の提案）

本人は現実の時間との同期を避けたいと説明した。ゲーム内の暦と時計を持ち、ゲームを閉じている間に現実時間に合わせて生活費・行事を進めない案が合う。

有力な方式は、散策では時計がゆっくり進み、勤務・料理・移動・睡眠などは明示した時間を消費する組合せ。会話の選択・意味確認・家具配置・設定では止める案を候補とする。短い勤務を実際に遊ぶ方式と、勤務を選んで時間が進む方式も分けて考える。

例として「ゲーム内2時間の勤務」を選ぶなら、開始前に終了予定を表示する。ミニゲーム中に経過した分と、終了時に加算する分を二重計上しない。仕事中に閉店・行事終了・深夜を跨ぐ場合も、一つの時計で処理する。配達に必要な短い実時間タイマーと、季節を動かす生活の時計を混同しない。

- 時計：店の営業時間、住民の居場所、朝昼夕夜、勤務の予定。
- 暦：曜日、季節、行事の期間、家賃等の周期。
- 天候：地域と季節に応じた見た目と活動の差。全ての地域の冬を雪にしない。
- 待つ・眠る：希望の時間や季節へ進む手段の候補。大きく進める前に予定を表示する。
- 暦の長さ：現実と同じ月日を短縮した時計で回すか、季節の日数自体を縮めるかは未決定。毎季28日等へ勝手に固定しない。
- 祝日の扱い：実在の固定日・移動日・地域差をゲーム暦へどう対応するかを定める。現実のある年の開催日を毎年の恒久ルールにしない。

比較として、攻略資料Serebiiは『ポケットモンスター スカーレット・バイオレット』の昼夜一周を72分と説明する。ただし非公式の資料で、本担当の実測ではなく、ポケモン全作品に共通の値ではない。このゲームに72分を採用する決定でもない。

## 6. 普段の町と、季節の催し

「プレイヤーが町並みを変えられない」と「季節に応じて制作側が町の姿を変える」は両立する。基礎の道・建物は固定し、季節・天気・行事によって店先、飾り、照明、売り物、露店、人出、短い会話、音が変わる案。

毎日特別な出来事を起こさない。普段の日も買い物・仕事・料理・住民の一言・散歩・部屋づくりで過ごせることを重視する。

行事は少なくとも次の三種を区別する。
1. その国・地域で実際に行われる祝日・祭り。
2. 特定の町で行われる催し。
3. ゲーム独自の催し。実在の文化として説明しない。

本人のクリスマスの例について、フランスのストラスブール市の公式案内は、冬の通り・広場の照明と飾り、歩いて巡る複数の市場、オーナメントや手工芸品・菓子等を紹介している。これはその地域の例であり、「フランスの全ての町で同じ催し」「ある国に屋台が一切ない」という分類には使わない。

催しは一日だけの必須参加にするより、準備・開催期間・片付け等を持たせる案が考えられる。飾りを買って家へ持ち帰る、期間中だけの短い仕事、季節の料理、住民の一言があると、日常とつながる。期間・内容は未決定。

## 7. 人数と固定の短い会話

### 7.1 町の人を増やすときの考え方

12～20人だけに縮めることを既定の完成目標にしない。**会話可能な人物を50～100人等の規模で検討する案**はあるが、本人がこの数を決定したわけではない。町数・地図・会話・人物素材を照らして最終人数を決める。背景の通行人を足すだけで「話せる人を増やした」とは扱わない。

住民全員に同じ長さの物語は必要ない。店員・近所の人・よく会う常連・時々来る人など、役割と顔、居場所、生活の時間、興味や口調を変える。固定セリフでも、時刻・天候・季節・仕事中・買い物・初対面・前に選んだ返し等で話題を変えられる。同じ意味の文を水増しして会話量としない。

例として80人に通常の短いやり取り10本ずつ用意するだけでも800本になる。さらに状況差分・返答・音声・校閲が必要になる。この計算は制作量の説明であり、採用する人数や最低会話数ではない。

### 7.2 教科書の完全な文に固定しない

本人が示した日本語での雰囲気：
- 「あ、それ好き。こっちの方がもっと好きかも」
- 「それのこういうところ好き。めっちゃ好き」
- 「いや、それちょっと苦手なんだよね」

これを各言語の自然な言い方として作る。日本語の語順や省略をそのまま翻訳して正解教材としない。相手・関係・場面に合わせ、顔見知りにはくだけた返し、接客には短く丁寧な返し等を用意する。

好みや気持ちの選択は、複数の返しが自然に成立する。好き・別の方が好き・苦手等を語学の正誤問題にしない。選んだ意図に沿って相手が短く反応すれば、一往復で終わってよい。毎回会話を引き伸ばさない。

セリフ・選択肢には、意図（共感、好み、軽い断り等）、関係に合う調子、使える場面、音声、日本語の意味を持たせる案。訳と解説は任意に確認できる。選択肢を選べたことは自発的に文を作った能力と分ける。

### 7.3 タイピングの役割

既存要望のタイピング・音声再聴・国別配列の入力補助は残す。全住民との会話でタイピングを必須にする指定ではない。仕事の品名・数量の確認、スマホ連絡、料理、任意の入力練習等へ目的を持って配置する案。選択で雰囲気を楽しむ会話と、綴りを練習する課題は両立できる。

## 8. 次の仕様化で必要なこと

| 決めること | 必要な理由 |
|---|---|
| 一作目の国・言語・町、現実を参照する程度 | 街並み・服・店・料理・行事・会話が変わる |
| 視点、人物の等身、端末、操作 | 歩く楽しさと家具配置のしやすさ、動作性能を確かめる |
| 一つまたは複数の町、住居候補の違い | 引っ越す動機と制作する景色・建物の量を決める |
| 間取りテンプレート、床と壁の配置規則 | 何を置けて何が使えるかを迷わず実装する |
| 壁際の机についての「壁判定が消える」の意味 | 設置枠の競合と壁の描画を取り違えない |
| 仕事・報酬・生活費・装飾品 | 働く時間と自由に暮らす時間の釣り合いを取る |
| 時計と暦、行事の期間 | 学習の確認中に追われず、季節を体験できる速さにする |
| 会話可能な人数・話題・口調・条件 | 固定セリフでも町の人に違いを感じられるようにする |
| 料理の深さと用途 | 買い物、台所、仕事、住民への贈り物等をつなげる |
| 生活中の学習支援・任意の練習 | 雰囲気を楽しむ操作と、理解・入力の練習を両立する |
| 短期・長期の遊びの目標 | 好きな部屋、料理、服、行きつけ、人、行事等が生活の動機になる |
| 保存・復帰・予定の確認 | いつ中断しても戻り、住居や家具、仕事の状態を失わない |

人物の多さ、住居の選択、季節の豊かさを完成版の目標として残しつつ、最初に動作を確かめる一連の体験を定める。初回の確認が小規模でも、完成仕様まで12語・固定画面へ縮めたと扱わない。
