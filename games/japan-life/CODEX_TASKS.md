# Codexへの制作依頼と、段階ごとの確認

2026-10-18。対象は games/japan-life/。以下は制作を依頼するための手順で、別のCodexタスクを起動済みという意味ではない。

## 1. 使い方

Codexでこのリポジトリを作業対象として選ぶ。クラウド環境なら、対象リポジトリとブランチを確認する。ローカルなら最新版を取得したフォルダを開く。チャット履歴を自動で全て読めるという前提にせず、本ファイルとSPECを読ませる。

通常の実装を行えるタスクで下の依頼文を渡す。計画だけで終了するモードを選んだ場合は、計画を確認してから実装へ進める。資料の保存は別のCodexセッションへの自動実行ではない。

## 2. 最初に貼る依頼文

> このリポジトリの AGENTS.md と docs/START_HERE.md を読み、日本の生活ゲームを games/japan-life/ に実装してください。
>
> games/japan-life/README.md、SPEC.md、CONTENT_PLAN.md、RESEARCH.md、CODEX_TASKS.md を仕様として使ってください。最初の対象は下記M1とM2です。短い実装計画を残したら、そのままコード・素材・起動・動作確認まで進めてください。
>
> 日本の架空の港町を主人公が3Dで歩き、店へ入り、会話・買い物・喫茶店勤務・期限つき複数配達・自宅料理・賃貸一室の家具配置・着替え・睡眠・保存を一巡できる状態にしてください。固定画面のタイピング問題へ置き換えないでください。住居は同時に一つです。
>
> 初期の町名・地域・数値は変更可能な制作案です。料理は出典とゲーム用の省略を分けてください。60人の名簿と固有の会話の種を使用し、M2では全員に会えて最低一往復できる状態を作ってください。M3の会話量や季節をM2だけで完成したことにはしないでください。
>
> 動く範囲を実際のブラウザで確認し、できたこと・未確認点・残件を README と TESTING.md と進捗表へ記録してください。ソースだけでなく、利用者が遊べる配布物か具体的な配信手順を用意してください。アクセスできないlocalhostやクラウド内パスを手元で遊べるURLとは案内しないでください。
>
> 場所ごとのBGM、ラジオ取得後の自宅選曲、音量と消音、読み上げ中の音量低下、選曲の保存もSPEC §16に従って含めてください。仮の音源を完成曲と扱わないでください。
>
> 外部生成AI・APIキーは必須にしません。既存 games/english-errands/ とシェアハウスは変更しないでください。全言語共通エンジンを先行開発しないでください。

長い依頼が扱いにくければ、次でも入口になる：
> AGENTS.mdとdocs/START_HERE.mdを読み、games/japan-life/CODEX_TASKS.mdの最初の依頼に従って、M1・M2を実装・動作確認してください。仕様だけで終わらず、歩いて暮らせる状態と遊び方を示してください。

## 3. M1：町を実際に歩く

### 作ること
- 対象フォルダ内に動作するWeb3Dの開発・ビルド環境。採用ライブラリの版を固定する。
- 三人称の主人公、PC・タッチ操作、カメラ衝突、当たり判定、入口からの室内切替。
- 海辺・商店街・住宅・駅前公園の四地区と、店内・賃貸候補三室。
- 日本の町の見え方を考えた、軒、窓、扉、看板、商品、生活小物と音。単なる同じ箱の列を景観完成としない。
- 会話や買い物等を開く基本UI、ゲームの時刻、地図、設定。
- 町・店・自宅のBGM切替、音量・消音、ユーザー操作後の音声開始。
- 60人の名簿・役割・居場所をデータへ登録。

### 確認
- 起動→自室→外→商店街→海→公園→帰宅まで歩ける。
- 視点が建物や人物の内側へ入り続けない。道・出入口が塞がっていない。
- 海・市場・住宅の景色が分かれ、現地を歩く目的がある。
- 入力UI中にWASDやタッチが誤って主人公を動かさない。
- 一画面のモック画像や地図上の点移動だけをM1達成にしない。

## 4. M2：日常の一巡を遊ぶ

### 作ること
- 部屋の内見と選択、同時一住居、転居、保管箱。
- 物理的に置ける25家具（ラジオを含む）、床と壁の設置、回転・取消、出口と使用位置の確認、カーテン・机上小物。
- 服12点と見た目への反映。
- 店の営業時間、食材16品、家具・服・明石焼器、数量・価格・所持品のやり取り。
- 料理6品の材料と手順・手操作・完成品。
- 喫茶店の4客勤務、報酬と時間消費。
- スマホの受注、最大3件の配達、集荷と配達、期限・遅配・取消。
- 全60人に最低一つ専用の話題と返答2～3個、短い相手の反応。全員同時に描画しなくても、町で会える。
- 日付と営業時間、睡眠・待つ、月家賃。
- 読み・音声再聴・文字での代替、任意の入力とIMEへの配慮。
- 自動保存・再開、JSON移行、壊れた保存の案内。
- ラジオ取得による自宅選曲、試聴・決定・停止、TTS時のBGM低下、音楽と声の音量分離、選曲と音量の保存。

### 一巡の合格条件
1. 初めて起動し、三つの部屋を内見して一つ選ぶ。
2. 歩いて食材を買い、別の店や人へ立ち寄る。
3. 喫茶店で働く。注文を確認して渡せ、終わった時刻と報酬が一度だけ変わる。
4. 配達を二件受け、集荷・順路を選んで届ける。所持していない荷物は渡せず、重複報酬もない。
5. 家具を買い、自室へ戻って置き、回転・保管・取消を使う。
6. 壁の飾りと机を配置し、家具のせいで勝手に飾りが消えない。出口は使える。
7. 材料を選び、日常の料理と地域料理を一つずつ作れる。材料不足では中途半端に消費しない。
8. 服を変えると主人公の姿に反映される。
9. 寝て翌朝になり、終了して再開すると住居・配置・在庫・お金・日時・仕事が復元する。
10. 別の部屋へ引っ越しても住居は一つ、全家具は残る。
11. 60人のIDが違うだけでなく、役割と固有話題・場所に違いがある。
12. 日本語音声がなくても遊べ、その状態を音声による理解成功と記録しない。

13. 町→店→家で曲が切り替わり、同じ曲の区域をまたぐだけでは冒頭に戻らない。
14. ラジオ未取得では任意の選曲ができず、取得後に選曲できる。転居・保管・再開でも選択が残る。
15. 音声の再聴や取消の後でBGM音量が正しく戻り、音源欠落・再生拒否でもゲームが進む。無音設定を復帰で勝手に解除しない。

### M2の納品
- 実際に起動したビルド、ソース、依存固定、起動手順。
- 配布用ZIP等と、ゲームの動作に必要なファイルを含めた一覧。または利用者が手元で配信できる手順。
- ブラウザでの歩行・買い物・配達・部屋・料理の画面証拠。
- 意味のあるテスト：取引と消費・報酬の一度だけ処理、転居と家具保持、通路確保、時刻の大幅加算、IME、セーブの復元。
- TESTING.mdに実行したコマンドと結果、未実行と理由。日本語の自然さ・スマホ実機を自動で合格にしない。
- PROGRESS.mdにM1/M2の達成・不達、M3以降の残件。規模や実行枠で残ったものは、動く到達点と具体的な次の作業を残す。

## 5. M3：町に住み続ける内容

M2が動いてから同じゲームを育てる段階。旧試作や他言語へ脱線しない。

- 60人それぞれ6本以上の通常・状況会話と、季節の反応。名前を入れ替えただけの会話で水増ししない。
- 昼夜・天候・職場・買い物等で居場所と会話が変わる。
- 春夏秋冬の景観、四つの創作の町の催し。毎日がイベントになる頻度にしない。
- 催しの飾り、売り物、短い仕事、食べ物を生活へつなぐ。
- 家具と服、料理を本人のプレイ結果に基づいて追加。追加レシピは地域資料を確認してから。
- 目標のない散歩の日、仕事で稼ぐ日、料理や部屋の日がそれぞれ成立する。
- 初心者向けの読み・音声・意味、任意のタイプを流れを止めすぎない形へ改良。
- 日本の港町・店・自宅の音楽を本人の試聴で磨き、季節や催しの違いを加える。音源・作者・条件・ループと再生結果を記録する。
- 完成用モデルや音へ置換。仮素材を残すなら一覧と制限を出す。
- タッチ・スマホ実機で操作、性能、音声を確認し、その結果で軽量化する。
- 日本の別の町は、この町の暮らしが成立した後に必要性を見て設計する。一町だけでも作品として成立させる。

## 6. M4：公開前の確認

- 本人の日本語・暮らし・景色・食文化の確認を反映。特定の地域を全国の共通習慣と断定しない。
- 学習者向けに公開する場合、案内言語、対象レベル、読み、教材と許容表現を確認。学習効果が実証されたとは表示しない。
- 素材条件・第三者の表示、外部依存、保存・削除、配布物、対象ブラウザを確認。
- 実機を含む連続プレイ、中断復帰、転居、行事と月替わり、全仕事の完了経路を確認。
- 完成仕様との未対応を残したまま「全部完成」と報告しない。
